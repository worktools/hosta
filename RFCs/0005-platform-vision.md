# RFC 0005：平台愿景与 Vercel 式开发者体验

- 状态：Proposed
- 日期：2026-08-10

## 1. 背景

Hosta 的 MVP 已打通"描述 → 生成 → 试运行 → 发布 → 调用"的主流程。现在需要从产品视角重新审视平台定位，参考 Vercel 等低门槛研发平台的设计哲学，将 Hosta 定位为**以 LLM 代码生成为核心的、面向轻量级小程序（mini-app）的研发平台**。

Vercel 的核心价值主张：

- **零配置部署**：连接 Git 仓库即可自动构建部署
- **即时预览**：每个 PR 自动生成预览环境
- **边缘网络**：全球 CDN 和 Serverless 运行时
- **开发者体验优先**：CLI、Dashboard、分析一体化

Hosta 的差异化：

- **自然语言输入 → 可运行程序**：不需要写代码，描述需求即可
- **小程序粒度**：每个程序是独立的、可调用的微型服务
- **LLM 驱动的全生命周期**：生成、测试、修订、优化均由 AI 辅助
- **数据感知**：每个程序可绑定数据源，支持数据迁移

## 2. 平台定位

Hosta 是一个 **LLM-first 的小程序研发平台**：

```text
用户描述需求 → LLM 生成代码 + 测试 → 沙箱验证 → 发布 → HTTP 调用
                  ↑                              ↓
                  └── 运行反馈 → LLM 修订 ←──────┘
```

### 2.1 核心概念

| 概念                  | 说明                                                         | 类比 Vercel                |
| --------------------- | ------------------------------------------------------------ | -------------------------- |
| Program（程序）       | 一个可独立运行的小程序，有自己的代码、版本、数据源和调用入口 | Project                    |
| Version（版本）       | 不可变的代码快照，每次生成或编辑产生新版本                   | Deployment                 |
| Data Source（数据源） | 程序绑定的 JSON 数据，支持版本化的快照和迁移脚本             | KV / Blob Store            |
| Publish（发布）       | 将指定版本设为线上版本，生成稳定的调用地址和密钥             | Production Deployment      |
| Invoke（调用）        | 通过 HTTP GET/POST 调用已发布程序                            | Serverless Function Invoke |

### 2.2 设计原则（继承 RFC 0001 并扩展）

- **版本先于应用**：每次生成/编辑产生不可变版本
- **试运行先于发布**：必须至少一次成功试运行才能发布
- **AI 是建议者，人是决策者**：LLM 生成代码，用户确认发布
- **数据与逻辑分离**：数据源独立于代码，支持迁移和回滚
- **小程序可组合**：程序之间可通过 HTTP 互相调用
- **渐进式能力**：默认最小权限，按需开启网络、数据源等能力

## 3. 用户旅程（Vercel 式体验）

### 3.1 首次体验（< 60 秒到首次运行）

1. 打开网页，看到空状态引导："描述你的第一个自动化"
2. 输入自然语言描述（如"汇总订单金额"）→ 点击"生成"
3. LLM 自动生成代码、测试用例和示例输入
4. 系统自动运行测试，展示结果
5. 用户可手动试运行，修改输入查看输出
6. 点击"发布"，获得调用地址和密钥

### 3.2 迭代开发

1. 用户修改代码或点击"根据错误修订"
2. 系统生成新版本，自动运行测试
3. 测试通过后，用户手动试运行确认
4. 点击"设为默认版本"切换线上版本
5. 旧版本保留，可随时回滚

### 3.3 小程序互联

1. 程序 A 发布后获得调用地址
2. 在程序 B 的代码中，通过 `ctx.call(appCode, input)` 调用程序 A
3. 平台自动处理认证和服务发现

## 5. 与 Vercel 的对比

| 维度     | Vercel           | Hosta                          |
| -------- | ---------------- | ------------------------------ |
| 代码来源 | Git 仓库         | LLM 生成 + 手动编辑            |
| 部署粒度 | 全栈应用         | 单个小程序函数                 |
| 运行时   | Edge/Serverless  | vm.createContext (JS) / WASM   |
| 数据存储 | KV/Blob/Postgres | JSON 数据源 + 快照             |
| 预览环境 | 每个 PR 自动生成 | 每个版本可独立运行             |
| 回滚     | 秒级回滚         | 切换到任意历史版本             |
| 组合     | 微服务/API 路由  | 小程序间 HTTP 调用             |
| 定价     | 按使用量         | 本地免费 / 云端按 token + 调用 |

## 6. 后续阶段规划

### Phase 2：小程序互联与扩展

- 程序间 HTTP 调用（`ctx.call`）
- 外部数据源接入（REST API、Webhook 数据源）
- Secrets 管理
- 程序模板市场

### Phase 3：网络效应

- 公开程序目录（`/api/discover` 增强）
- 程序间带权限调用
- 外部 OAuth 数据源连接
- 多用户协作

### Phase 4：企业级

- 多租户治理
- 配额与计费
- 审计日志
- SLA 保障

# RFC 0013：独立 Hoya 引擎与双运行时 Serverless 平台

- 状态：Accepted for planning
- 日期：2026-09-06
- 依据：维护者当前目标——Hosta 是基于 WASM 和 QuickJS 的开源 serverless 平台，Hoya 独立维护。

## 产品定位

维护者补充（2026-09-06）：前期验证全部由命令行完成，Hosta 提供面向 agents 的 CLI。CLI/API 是主要操作入口，UI 先展示应用、版本、运行和健康状态；是否细化网页交互后续评估。首次部署及发布门槛不依赖浏览器。

Hosta 面向希望快速托管短函数的开发者与自动化使用者。核心价值是：无需自行搭建执行基础设施，即可创建、测试、发布和诊断一个可调用服务。AI 生成是可选入口，模板和已有代码具有同等地位。首个稳定场景是 JSON 转换与 Webhook；受控出站 API 调用在网络策略完成后开放。

平台必须让用户清楚知道：当前编辑与运行的版本、线上版本、运行时和可用能力、发布对调用方的影响，以及失败后如何处理。不能把编译器安装、内部协议差异和引擎错误未经解释地交给用户。

## 仓库边界

| Hosta | Hoya |
| --- | --- |
| Agent CLI、展示 UI、管理 API、应用与不可变版本 | QuickJS、Wasmtime 执行实现 |
| 生成任务、源码构建与产物存储 | 稳定执行协议、guest ABI、能力发现 |
| 发布指针、鉴权网关、触发和运行历史 | 隔离、时间/内存/日志限制、受控 host APIs |
| 引擎客户端、部署编排与兼容检查 | 独立二进制/镜像、契约 fixtures 与版本发布 |

两仓库通过固定版本的 HTTP 协议和产物 hash 交互；Hoya 不持有 Hosta 数据库或模型密钥。源码构建独立于执行，不能把任意源码编译作为引擎调用的隐含动作。首版不要求 Hoya 改成可发布 crate。

## 双运行时与阶段

QuickJS 与 WASM 同属核心方向，面向用户统一 JSON 输入、JSON 结果、结构化日志、状态及错误分类。保留各自明确的语言/API 支持边界，不承诺 Node/npm、完整浏览器 API 或任意 WASI 应用兼容。

先固定协议及 ABI，接通真实引擎和基础 CLI，再完善命令行的版本上传、试运行、发布和诊断闭环，最后交付可复现的开源预览版。CLI 使用稳定 JSON、明确退出码、stdin/文件输入及显式版本，支持 agent 非交互调用。Rust WASM 先通过真实 JSON 场景；MoonBit 经相同兼容测试后开启。执行完整性和资源限制是 A0 门槛。

多租户、计费、全球调度、自动扩缩容、工作流市场和自主发布不在当前交付范围。许可证由维护者选择，计划不代替授权决定。

## 对既有 RFC 的修订

- 替代 RFC 0001/索引中的“AI 软件工厂是唯一入口”和“仅 JS”范围；沿用不可变版本、测试后发布和失败可理解原则。
- 替代 RFC 0002 的“从 Hoya 提取/改写 Runner”决策；内部协议示例仅为历史草案，正式 schema 由 Hoya 维护。
- 替代 RFC 0004 的 monorepo、内嵌 crates/runner 和旧里程碑顺序。新顺序为 A0/A1/A2，见开发计划。
- RFC 0003 的状态机、发布原则可继续作为设计参考；其 API、模块入口和时限需按 v1 协议验收，不能视为当前实现。
